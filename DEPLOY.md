# Деплой SaudaCRM

VPS без домена и HTTPS, один пользователь. Всё крутится в Docker, команды — через `make`.

Сервисы: `db` (PostgreSQL), `web` (Django+gunicorn), `bot` (Telegram), `cron` (утренний дайджест), `backup` (ежедневный дамп).

---

## 1. Подготовка сервера

Нужны только Docker и Docker Compose:

```bash
curl -fsSL https://get.docker.com | sh
```

Проверить: `docker compose version`.

## 2. Первый запуск

```bash
git clone <репозиторий> saudacrm && cd saudacrm
cp .env.example .env
```

Заполнить `.env`. Обязательно:

| Переменная | Что писать |
|---|---|
| `SECRET_KEY` | `python3 -c "import secrets; print(secrets.token_urlsafe(50))"` |
| `DEBUG` | `False` — иначе наружу утекают трассировки с настройками |
| `ALLOWED_HOSTS` | IP сервера, напр. `203.0.113.10` |
| `CSRF_TRUSTED_ORIGINS` | со схемой и портом: `http://203.0.113.10:8000` |
| `DB_PASSWORD` | длинный случайный пароль |
| `BOT_TOKEN` | токен от @BotFather |

Поднять:

```bash
make up
make superuser
```

Админка: `http://<ip>:8000/admin/`

## 3. Разовый импорт из Excel

Делается **один раз на пустой базе**, сразу после первого запуска.

```bash
# на своей машине
scp "Учет товаро Атай.xlsx" user@server:~/saudacrm/import/

# на сервере
make import FILE="Учет товаро Атай.xlsx"        # предпросмотр, в базу НИЧЕГО
make import-apply FILE="Учет товаро Атай.xlsx"  # запись (бэкап снимется сам)
make import-clean                                # убрать файл с сервера
```

Предпросмотр сам сверяет результат с листом «Показатели» — если выручка и себестоимость по месяцам сходятся в ноль, импорт корректен.

**Выгрузка должна быть свежая, снятая в день деплоя.** За две недели между двумя присланными файлами долг упал на 400 тысяч и списались две партии — старый срез даст неверные остатки.

После импорта: зайти в админку и проставить фасовки у 17 товаров (в таблице их нет, всем ставится «мешок»).

## 4. Бэкапы

Данные тут дороже всего остального, поэтому схема с запасом.

**Что работает само.** Сервис `backup` каждую ночь в 3:00 снимает дамп и раскладывает:

```
backups/daily/    последние 30 дней
backups/weekly/   каждое воскресенье, 12 копий
backups/monthly/  каждое 1-е число, 12 копий
```

Трёхуровневое хранение нужно на случай, когда порчу данных замечают не сразу: если ошибка всплывёт через полгода, месячная копия всё ещё на месте.

**Дамп проверяется, а не просто пишется.** Пишем во временный файл, проверяем размер и целостность архива, и только потом кладём в `daily/`. Молча испорченный бэкап хуже отсутствующего: о проблеме узнаёшь в момент, когда уже поздно.

**Команды:**

```bash
make backup          # снять прямо сейчас (перед любой рискованной операцией)
make backups         # что есть
make backup-verify   # развернуть последний бэкап во временную базу и проверить
make logs-backup     # что делает сервис бэкапов
```

`make backup-verify` — единственный честный способ узнать, что бэкап рабочий. Стоит прогонять раз в месяц.

**Восстановление:**

```bash
make restore FILE=backups/daily/saudacrm_2026-09-22_0300.sql.gz
```

Спросит подтверждение, сам снимет бэкап текущего состояния перед заменой.

### ⚠️ Чего схема НЕ закрывает

Бэкапы лежат **на том же сервере**. Умрёт диск или пропадёт доступ к VPS — исчезнут и база, и копии. Это единственная точка отказа, которая осталась.

Минимальное решение — забирать копии к себе раз в неделю:

```bash
rsync -az user@server:~/saudacrm/backups/weekly/ ~/saudacrm-backups/
```

Вопрос, куда дублировать наружу, вынесен в `questions_atay_2.txt` (пункт 4.2) — ждёт решения.

## 5. Повседневные команды

```bash
make ps           # что работает
make logs         # логи всех сервисов
make logs-bot     # только бот
make restart      # перезапустить приложение
make update       # забрать новый код, пересобрать, накатить миграции
make shell        # Django-шелл
make psql         # psql к базе
make digest-preview   # посмотреть дайджест, не отправляя
make digest           # отправить дайджест сейчас
```

## 6. Тонкости, о которые легко споткнуться

**Локаль базы — `C`, и поменять её потом нельзя.** Задаётся при создании базы в `docker-compose.yml`. В `en_US.UTF-8` русские названия с пробелом («Масло растительное») сортируются после «тест» — ломается порядок товаров в списках и отчётах. Мы на это уже напарывались на дев-базе. Смена локали потом = пересоздание базы с переливкой данных.

**Бот должен работать в одном экземпляре.** Telegram не даёт двум процессам читать обновления одного бота: второй будет получать `Conflict`. Не запускать `runbot` руками, пока поднят контейнер `bot`.

**Миграции накатывает только `web`.** Если бы это делали и `web`, и `bot` одновременно, они налетали бы друг на друга. `bot` ждёт, пока схема обновится.

**`DEBUG=False` обязателен**, и именно поэтому в проекте whitenoise: без него gunicorn не отдаёт статику и админка Unfold открывается «голой».

**Порт 8000 публикуется наружу, HTTPS нет.** Значит пароль от админки идёт по сети открытым текстом. Варианты:

- оставить как есть — проще всего, но пароль перехватываем в теории;
- закрыть порт и ходить через SSH-туннель: убрать `ports` у `web` в compose и открывать `ssh -L 8000:localhost:8000 user@server`. Безопасно, но только с машины с доступом по SSH;
- позже завести домен и сертификат — тогда снимается совсем.

Решать вам; по умолчанию порт открыт, потому что Атаю нужен доступ с телефона.

**База наружу не торчит** — у сервиса `db` нет проброшенных портов, доступ только изнутри и через `make psql`.
